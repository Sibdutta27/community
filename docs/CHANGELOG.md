# Changelog

All notable changes to the Community monorepo are recorded here, categorized by
`[app/domain]` (see `docs/architecture/categories.yaml`). Maintained by the
`change-router` skill (`/change-router log <description>`). Format follows
[Keep a Changelog](https://keepachangelog.com/).

`app` ∈ `backend | web | admin`. `domain` ∈ the keys in `categories.yaml`
(`auth`, `enrollment`, `consent`, `documents`, `services`, `events`, `profile`,
`cultural-connection`, `feedback`, `admin-management`, `marketing-content`).

## [Unreleased]

### Added

- [backend+web+admin/marketing-content] **Website Studio — a CMS inside the admin panel** (2026-08-12): staff edit the public site's copy, yukayeke territory details and images without a deploy. Copy is stored as **DB overrides layered over the git catalogs**, never as a replacement — `apps/web/src/i18n/request.ts` merges published overrides onto `messages/{en,es}.json`, so an unreachable API renders exactly what shipped. Four tabs: **Pages** (English beside Spanish, sections collapsible because Home alone holds 137 strings, publish/revert), **Yukayeke** (display name, cacique, municipalities, also-known-as, status editable; slug, map key, legal name and API names locked as record facts with reasons — they back the GeoJSON join and the enrollment `@IsIn`), **Media** (uploads to a **separate public bucket**, since `S3_BUCKET` holds identity documents; SVG refused as a stored-XSS vector; ~10 slots with git-registry fallbacks) and **History** (every publish/restore with actor and before/after in both languages). New models `ContentKey`/`ContentString`/`ContentRevision`/`ContentVersion`/`TerritoryOverride`/`ContentMedia`/`ContentImageSlot`; `pnpm --filter yucayekeconnect-server content:sync` projects the catalogs into the registry. The Pages tab shows the live site in an iframe beside the editor, with language passed as `?lang=` → `x-locale` because the locale cookie is third-party in a frame. **Override writes are refused unless they declare exactly the placeholders their default declares** — dropping `<highlight>` from `home.hero.title` would take the homepage down — and the enrollment/profile/auth namespaces are refused outright — apps/api/src/modules/content, apps/admin/src/pages/Website, apps/web/src/i18n

- [backend+admin/enrollment] **Rejection reasons + a decision-notice queue** (2026-08-11): rejecting an application was a bare boolean behind a `window.confirm`, so nothing was recorded and a decision could not be explained to the applicant later or reviewed if challenged. `Enrollment` gains `decisionReason` / `decidedAt` / `decidedById`; `PATCH /admin/enrollment/:id/verify` accepts optional `reason` + `channels` (both optional so the API can deploy ahead of the panel). New `EnrollmentNotice` table + `NoticeChannel` / `NoticeStatus` enums and `GET /admin/enrollment/:id/notification-channels`, which offers only the channels the member actually registered. **No mail or SMS provider exists in this API** — a chosen channel writes a `PENDING` row and nothing claims delivery; asking to text a member who never set `Contact.allowSMS` writes `SUPPRESSED` instead of a sendable row, and destinations are snapshotted at decision time. Admin gets a reject dialog stating plainly that sending is not connected. Migration `20260812010000_add_enrollment_decision_record` is additive (nullable columns, new empty table, rollback in comments) and was applied to the `public` schema — **`prod_sim` still needs it before testing-prod takes these commits** — apps/api/src/modules/admin/adminEnrollment, apps/admin/src/pages/Enrollments/components/RejectDialog
- [admin/admin-management] Global search as a **⌘K command palette** rather than a permanent field: ~110px trigger in the 44px bar, opens from anywhere, jumps to any section or finds a member (server-side search, arrow keys and Enter crossing group boundaries). The box it replaces was wider and wired to nothing — apps/admin/src/components/CommandPalette
- [admin/admin-management] **Real overview dashboard**, now routed as the landing screen: enrollment status counts, feedback triage counts, role counts, the next 30 days of events and the latest applications. It previously rendered invented SaaS metrics ("Total Revenue $24.8k", "New Orders 342") and was not routed at all. A count that fails to load renders as an em dash rather than a zero — apps/admin/src/pages/Dashboard

### Changed

- [web/marketing-content] **The home hero makes the offer instead of describing it** (2026-08-13): the centred stack becomes a left-aligned two-column layout whose right side is a **sample tribal ID card turning in 3D**, which visitors can grab and fling — releasing hands it back to its drift rather than parking it. The card is deliberately **unissued and unattributed**: real chrome (seal, wordmark, field labels), ruled blanks where the values go, an "Unissued" badge, no name, no likeness, not even a fictional member — so the visitor sees the credential they do not have yet, and nothing here can be screenshotted and passed off as an issued card. Its reverse is the existing Yukayeke face with the Borikén territory map. `PageHeroSection` gains an optional `innerClassName`; it defaults to today's centred reading column, so the about/contact/services/community/enrollment/yucayeke heroes are untouched. CTAs drop `xl`→`lg` and the secondary goes `outline`→`ghost` so it stops competing with the flag-red pill; stacked on mobile the ghost is pulled back by its own padding to sit on the column edge. **Two motion firsts in this app** — a continuous animation and a drag — so: the rAF loop is gated on `useReducedMotion()` explicitly (neither the app-wide `MotionConfig` nor the global `prefers-reduced-motion` CSS stops a rAF loop), rotation is written straight to `style.transform` rather than through React state so the SVG-bearing reverse face does not re-render 60×/s, `touch-action: pan-y` keeps a vertical swipe scrolling the page, and both faces are `inert` under one `role="img"` since rotating text is no place for a screen reader. **Knowingly in tension with WCAG 2.2.2**, which would want a pause control for motion that auto-starts and runs past five seconds; `prefers-reduced-motion` is the only escape hatch shipped — apps/web/src/features/home/components/spinning-id-card.tsx, apps/web/src/features/home/components/home-hero.tsx
- [web/marketing-content] **The home page grows a background** (2026-08-13): every section after the hero flips to white and the hero keeps the tinted `--background`, so the two finally read as different surfaces instead of one continuous panel — cards inside those sections take the tint in exchange, keeping the separation the old arrangement got for free. The hero gains a faint 4rem square grid, ink-tinted at 4.5% and masked out over its last third so it dissolves into the white rather than ending on a seam. `home-mission-feature` takes `--surface-muted` instead, because it is shared with `/about` and needed a tone that reads on both grounds. `/enrollment` inherits the same treatment through the two sections it shares with home. The hero's CTAs swap sides — quiet left, flag-red right — via DOM order plus `flex-col-reverse`, so a phone still stacks the primary action on top. The card's reverse becomes generic: the whole island with no territory singled out and "Your Yukayeke" where a name would be, matching the unissued front, since a sample card that highlights a real yucayeke is claiming one — apps/web/src/features/home
- [web/profile] The tribal ID's front face is extracted to `tribal-id-card-face.tsx`, leaving `tribal-identification-card.tsx` as the face plus its export actions (2026-08-13). `@/lib/download` is imported at module top, so rendering the old component on the landing page would have shipped **jsPDF and html-to-image to every marketing visitor** — verified via the client-reference manifests that `/` now loads none of that chunk while `/profile` still does. The face gains a `blank` presentation and the reverse face a `bare` one (card only, no action row — its links would otherwise sit inside an `inert`, continuously rotating element and break the height the two faces share). The card gradient and glow are now imported by the reverse face rather than restated, so the two chromes cannot drift — apps/web/src/features/profile/components/tribal-id-card-face.tsx

- [admin/admin-management] **One product identity across both apps**: the sidebar's placeholder "A / Community" mark becomes the member app's seal and "Taíno Nation of Borikén" wordmark with "Admin" as the surface label; tab title and favicon follow; the package stops being named `reactskeleton` (now `yucayekeconnect-admin`, matching `yucayekeconnect-web`) — apps/admin/src/components/Sidebar

### Fixed

- [backend/marketing-content] The public content read carried `s-maxage=60, stale-while-revalidate=600`, which **defeated the entire publish flow** (2026-08-12): the web app busts its Data Cache on the revalidate hook, re-fetches, and the edge returns the same stale copy — so a published edit stayed invisible for up to ten minutes while publish, the webhook and the API all reported success. Every local test passed; there is no edge in front of a dev server. Found only by the new cross-app Playwright `cms` project and now guarded by `content.controller.spec.ts` — apps/api/src/modules/content/content.controller.ts
- [admin/admin-management] Four defects found during the density pass (2026-08-11): rows in the **All / Approved / Rejected** enrollment lists were inert — the `<Link>` was commented out and pointed at `/users/edit/`, so only the Submitted queue could open an application and staff could never reopen a decided one; a **bulk role change never invalidated the user list**, leaving the table showing pre-change roles; `UserList` destructured its fetch error and never read it, making a failed load indistinguishable from "no users"; and **both category lists computed their search/pagination filters then called the query with `{}`**, so searching or paging Service Categories and Event Categories did nothing (the service one was masked by a lowercase component name that made ESLint report its hook calls as rules-of-hooks violations instead). Admin lint is now clean — 0 errors, down from 12 — apps/admin/src/pages
- [web/profile] The profile page was unreachable on mobile (2026-08-11): the account menu holding the only `/profile` link lives in a `hidden … lg:flex` container, and the member's own card at the top of the mobile drawer was a static `div`, so a phone had no route to the profile page at all. That card is now the account control — tapping it discloses **Profile** and **Sign out**, mirroring the desktop avatar menu, with a rotating chevron carrying the affordance (`aria-expanded`/`aria-controls`, `role="menu"` children at `py-3` touch targets, collapsing whenever the drawer closes). The standalone Sign out button at the foot of the drawer is gone — account actions now sit in one surface, apart from navigation — apps/web/src/components/layout/protected-navbar.tsx
